## 目标与读者

读者是招聘方与项目评审。图表应让他们在 10–20 秒内理解一个项目独有的工程问题，并能继续追到源码、项目材料或测试。本站已有拓扑、时间线、三态决策板、家庭责任泳道与六张项目原图；新增图形必须补充新的关系，不能把现有段落再画一遍。

现有材料没有可比较的准确率、吞吐、延迟或真实用户结果。图形只使用已核对的结构、状态和工件；任何未来的量化图都要同时给出样本、单位、方法、环境和日期。

## 视觉方向

**主题：工程证据手册。** 图占主要面积，右侧保留窄幅“依据栏”，写明支持图中结论的文件／材料和仍未验证的边界。这里刻意让验证缺口可见，作为本站区别于普通作品集仪表盘的标识。

- 颜色沿用现站：雾绿 `#eef1ed`、墨色 `#171c20`、深青 `#2f666b`、浅冰 `#b8e2e5`、兰紫 `#80659a`。深青表示已由材料支持的主路径；虚线与淡紫表示条件分支或尚需验证的边界。不要用颜色独自承载含义。
- 字体沿用 Noto Sans SC / Manrope 做标题正文，IBM Plex Mono 做节点编号、接口名与来源注记。数字只表示真实顺序、端口或测试事实，不做视觉装饰。
- 图形用现有玻璃边框与细网格的节奏，但主体保持高对比度。项目原图仍留在证据图库里；新图尽量以可缩放的 SVG 或语义 HTML 绘制。
- 交互只做一处：悬停、聚焦或点选某一步时，高亮它的输入、输出和依据；移动端点选后在图下显示解释。无自动播放；减少动态偏好时直接切换状态。

桌面结构：

```text
工程问题标题                                      图例
┌───────────────────────────────────────────┬──────────────┐
│ 主图：请求/工件沿一条明确路径交接             │ 依据         │
│ 可点选节点，当前路径高亮                       │ 源码/项目书   │
│                                           │ 未验证边界   │
└───────────────────────────────────────────┴──────────────┘
```

手机结构：标题 → 图形（纵向重排，不靠横向滚动阅读）→ 当前节点解释 → 依据栏。若节点太密，默认只展示主路径，点选再展开细节。
